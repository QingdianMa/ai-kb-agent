# 技术档案

> 忘了配置、命令、版本、模型参数时来这里查。也包含已经踩过的坑——面试时这些都是可以讲的素材。

## 一、常用命令

```bash
# 启动（dev 模式：内存向量库，不需要数据库）
cd /d D:\ai-kb-agent
mvn spring-boot:run "-Dspring-boot.run.profiles=dev"

# 打包
mvn -DskipTests package

# 用打包好的 jar 启动
D:\JavaJDK\bin\java -jar target\ai-kb-agent-0.1.0-SNAPSHOT.jar

# 数据库（完整模式，需要 Docker）
docker compose up -d
```

访问地址：

| 地址 | 用途 |
|---|---|
| http://localhost:8080 | 演示页面 |
| http://localhost:8080/api/documents | 文档列表（含失败原因） |
| http://localhost:8080/api/chat/stream?question=xxx | 流式问答 |

## 五、踩坑记录（面试可讲）

| 现象 | 根因 | 解决 |
|---|---|---|
| `java -version` 是 8，`javac` 是 23，Maven 用的是 17 | 机器上三套 JDK，PATH 里排第一的是 Oracle Java 8 的影子入口 | 统一 `JAVA_HOME` 和 PATH 到 JDK 17 |
| Maven 每次构建都报 `Unrecognised tag: 'mirror'` | 全局 settings.xml 里 `<mirror>` 没放在 `<mirrors>` 元素内（还有个残缺的 profile 块） | 移入正确位置 + 注释残缺块，原文件已备份 |
| 上传报 500，日志显示 `{"code":20015,"message":"The parameter is invalid"}` | 请求体带了 `dimensions` 参数——那是 OpenAI 给 text-embedding-3 系列的专有字段，硅基流动不认 | 默认不发送，做成配置项 `KB_EMBED_SEND_DIMENSIONS` |
| 论文/证书类 PDF 只解析出几百字符 | 图片型 PDF，没有文字层，需要 OCR | 加入自动识别并告警（当前版本尚未接入 OCR） |
| 响应慢、流式效果消失 | DeepSeek 默认开启思考模式，思维链占了大量输出 token，且走 `reasoning_content` 字段不进入流式正文 | 默认关闭思考模式，做成配置项 |
| `.env` 里的 key 不生效 | Spring Boot 不会自动读取 `.env` | 配置 `spring.config.import` 按 properties 格式加载 |
| 大文档向量化一次请求全发 | 单请求过大容易被限流或超时 | 分批（默认 16）+ 指数退避重试 |
| `docker pull` 卡住不动的超时 | daemon 的 `registry-mirrors` 配置没生效（配置后没重启过 Docker），Docker 回退去直连 Docker Hub，国内不通 | 不改 daemon、不重启 Docker，直接在 compose 里写**全限定镜像名** `docker.m.daocloud.io/xxx` 绕过 |

> 这几条里最有面试价值的是第 3 条：OpenAI 兼容协议只是"兼容"，各家实现有差异，一个 OpenAI 专有字段会让国产服务返回含糊的"参数无效"。排查方法是**逐个参数做最小化变量测试**。

> 第 8 条也值得记住：**共享服务器上不要随便重启 Docker**，那会影响别人的容器。能通过写全镜像地址绕过去的，就不要动系统服务。

## 六、服务器与部署

### 服务器

| 项 | 值 |
|---|---|
| 公网地址 | `<your-server-ip>`（示例，实际部署时替换） |
| 系统 | Ubuntu 22.04 / 24.04 |
| 配置 | 2 核 / 4 GB 内存 / 40 GB 磁盘（最低建议） |
| 项目路径 | `~/ai-kb-agent` |
| 访问地址 | `http://<your-server-ip>:8080` |

> 如果部署到共享服务器，**只用自己的端口，不动别人的东西，也不重启系统级服务**。

### 部署架构

```
浏览器
  ↓ http://<your-server-ip>:8080
kb-app 容器（Spring Boot 应用，端口 8080）
  ↓ 容器内网络，主机名 postgres
kb-postgres 容器（PostgreSQL 17 + pgvector）
  ↓
kb-pgdata 数据卷（数据持久化，容器重建不丢）
```

两个容器都配了 `restart: unless-stopped`，**服务器重启后会自动拉起来**。

### 常用命令（都在 `~/ai-kb-agent/deploy` 目录下执行）

```bash
cd ~/ai-kb-agent/deploy

# 看状态
sudo docker compose -f docker-compose.prod.yml ps

# 看应用日志（实时）
sudo docker compose -f docker-compose.prod.yml logs -f app

# 重启应用
sudo docker compose -f docker-compose.prod.yml restart app

# 停止全部（数据卷保留）
sudo docker compose -f docker-compose.prod.yml down

# 部署或更新
bash deploy.sh
```

### 更新代码的正确流程

**不要用 `scp -r` 覆盖整个项目目录**，会把服务器上的 `.env` 冲掉。只传变化的部分：

```powershell
# 本机
cd D:\ai-kb-agent
mvn -DskipTests package
scp target\ai-kb-agent-0.1.0-SNAPSHOT.jar <user>@<your-server-ip>:~/ai-kb-agent/target/
```

```bash
# 服务器
cd ~/ai-kb-agent/deploy && bash deploy.sh
```


### 安全说明

- 访问口令校验在 `AccessTokenFilter` 里，只拦 `/api/**`，静态页面放行
- `deploy/.env` 存着 API key，权限设成 `600`，同机器其他用户读不到
- 口令第一次打开页面时输入，之后浏览器会记住
- **目前还没有做限流**，如果发现额度消耗异常，第一件事是换口令

## 八、配置项速查

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `KB_CHAT_MODEL` | deepseek-flash | 对话模型 |
| `KB_CHAT_THINKING` | disabled | 思考模式，可选 enabled |
| `KB_EMBED_MODEL` | BAAI/bge-m3 | 向量模型 |
| `KB_EMBED_DIMENSION` | 1024 | 向量维度 |
| `KB_EMBED_SEND_DIMENSIONS` | false | 是否发送 dimensions 参数，仅 OpenAI 系需要 |
| `KB_EMBED_BATCH_SIZE` | 16 | 分批向量化的批大小 |
| `kb.retrieval.max-results` | 6 | 每次召回片段数 |
| `kb.retrieval.min-score` | 0.35 | 相似度下限 |
